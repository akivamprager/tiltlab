# יום ההדגמה: חיבור ה־Pi ל־Mac בלי תלות ברשת של האוניברסיטה

הרשת האלחוטית של האוניברסיטה (eduroam) לא מתאימה להדגמה: היא דורשת שם משתמש וסיסמה אישיים על ה־Pi, היא חוסמת בדרך כלל תקשורת ישירה בין מכשירים, וכתובות `.local` לא עובדות בה. לכן ה־Pi לא מתחבר לשום רשת חיצונית. הוא **יוצר רשת משלו**, וה־Mac מתחבר אליה ישירות. כך ההדגמה עובדת אותו דבר בקמפוס, בבית, עם נקודה חמה מהטלפון או בלי שום רשת.

| דרך | איך מתחברים | כתובת לוח הבקרה | אינטרנט ב־Mac בזמן ההדגמה |
| --- | --- | --- | --- |
| **רשת Wi-Fi של ה־Pi** (ברירת המחדל) | ב־Mac: להצטרף לרשת `TiltLab` | `http://10.42.0.1:8000` | אין |
| **כבל רשת** (Pi 3B, הגיבוי) | כבל Ethernet מה־Pi למתאם USB-C ל־Ethernet ב־Mac, ולחכות כ־20 שניות | `http://10.56.0.1:8000` | יש (דרך ה־Wi-Fi של ה־Mac) |
| כבל USB-C (רק Pi 4 / Pi 5 / Zero, לא Pi 3B) | כבל מה־Mac ליציאת החשמל של ה־Pi. הכבל גם מספק חשמל | `http://10.55.0.1:8000` | יש |
| **בלי חומרה בכלל** | על ה־Mac: `python3 tiltlab.py --sim --dashboard` | `http://localhost:8000` | יש |

לוח הבקרה לא טוען שום דבר מהאינטרנט (אין גופנים או ספריות חיצוניים), כך שהוא עובד גם בלי חיבור.

## הגדרה חד־פעמית על ה־Pi (בבית, כשה־Pi מחובר לאינטרנט)

נדרשת מערכת Raspberry Pi OS Bookworm או חדשה יותר.

</div>

```bash
cd ~/tiltlab
sudo bash pi/setup_pi.sh            # or: --password 'your-pass'  (8-63 characters)
sudo reboot
```

<div dir="rtl">

הסקריפט:

1. יוצר נקודת גישה בשם `TiltLab` עם סיסמה, שעולה בכל הפעלה של ה־Pi. **רשמו את הסיסמה שהוא מדפיס בסוף.**
2. מגדיר את יציאת ה־Ethernet כך שכבל ישיר ל־Mac עובד (ב־Pi 4 / Pi 5 / Zero גם יציאת ה־USB-C). כשה־Pi מחובר בכבל לראוטר, הוא מקבל כתובת כרגיל.
3. מתקין שירות שמריץ את `tiltlab.py --zero --dashboard` אוטומטית בהפעלה. אין צורך ב־SSH או בטרמינל מול הכיתה.
4. משנה את שם ה־Pi ל־`tiltlab`, כך שגם `http://tiltlab.local:8000` עובד.

שום דבר לא משתנה עד ה־reboot, כך שחיבור SSH לא נקטע באמצע ההגדרה.

הסיסמה גם מונעת מאחרים בכיתה לשנות את המעגל מהטלפון שלהם: בלעדיה, כל מי שמחובר לאותה רשת יכול לשלוח פקודות ללוח הבקרה.

## ביום ההדגמה

1. **להניח את ה־Pi ישר** ולחבר לחשמל: ב־Pi 3B ספק micro-USB של 5V ו־2.5A לפחות, או מטען נייד טוב. בשנייה הראשונה הוא מכייל את "ישר" (`--zero`).
2. לחכות כ־30 שניות.
3. ב־Mac: להצטרף לרשת `TiltLab`. גיבוי: לחבר כבל רשת בין ה־Pi למתאם ב־Mac (כדאי לבדוק מראש שיש מתאם USB-C ל־Ethernet).
4. לפתוח את הכתובת מהטבלה. כדאי לשמור אותה מראש כסימנייה.

אם מציגים שקפים מהאינטרנט, להוריד אותם מראש: בזמן החיבור לרשת של ה־Pi אין ל־Mac אינטרנט. macOS עשוי להציג "אין חיבור לאינטרנט", וזה תקין.

## חזרה לרשת הביתית (לעדכונים, `git pull`, `apt`)

</div>

```bash
bash pi/tiltlab-net.sh home       # until the next reboot
bash pi/tiltlab-net.sh ap         # back to demo mode
bash pi/tiltlab-net.sh status     # what is connected + dashboard addresses
```

<div dir="rtl">

המעבר מנתק חיבור SSH שעובר דרך ה־Wi-Fi (חיבור בכבל לא מושפע). אחרי reboot ה־Pi תמיד חוזר לנקודת הגישה.

## פתרון תקלות

| תקלה | מה לעשות |
| --- | --- |
| הרשת `TiltLab` לא מופיעה | לחכות עוד דקה. אם עדיין לא: לחבר בכבל רשת, לפתוח `http://10.56.0.1:8000`, ולבדוק דרך SSH לאותה כתובת עם `bash pi/tiltlab-net.sh status` |
| כבל הרשת מחובר אבל הדף לא נטען | לחכות 30 שניות (ה־Pi מנסה קודם לקבל כתובת מראוטר). ב־Mac, בהגדרות הרשת של המתאם, לוודא ש־IPv4 על "DHCP" |
| שכחתי את הסיסמה | על ה־Pi: `sudo nmcli -s -g 802-11-wireless-security.psk connection show TiltLab-AP` |
| מחובר לרשת אבל הדף לא נטען | `journalctl -u tiltlab -f` על ה־Pi; בדרך כלל החיישן לא מחובר |
| ה־Pi נכבה או מציג ברק צהוב | אספקת חשמל חלשה. להחליף לספק של 2.5A לפחות |
| הבועה לא באמצע כשה־Pi ישר | ה־Pi לא היה ישר בהפעלה. `sudo systemctl restart tiltlab` כשהוא מונח ישר |
| כלום לא עובד | `python3 tiltlab.py --sim --dashboard` על ה־Mac: אותו לוח בקרה עם חיישן מדומה |

**חזרה גנרלית:** לנסות את כל התהליך פעם אחת בבית לפני ההדגמה, כולל הפעלה מחדש של ה־Pi וחיבור מה־Mac.
